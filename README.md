# 拷问书籍方法论 (qbs-skill)

> 先把问题拷问到收敛，再让书来回答，最后把答案锻造成技能。

把一个**卡住的问题**经六阶段流水线，做成有书籍出处、可独立调用、真实试跑过的 Skill：

```
①拷问 Grill → ②找书 Book → ③取文读章 Read → ④蒸馏 Distill → ⑤合成 Synthesize → ⑥试跑回书 Test
```

## 核心特性

- **拷问收敛**：设计树 × 前沿(frontier)轮次拷问，产出「问题规格书」——找书契约与验收契约二合一；拷问时定下的验收标准就是试跑的判定标准（闭环）
- **自依赖**：找书漏斗、阅读纪律、三层提取、三重验证、4+1 组装全部内化，无外部技能硬依赖
- **反幻觉纪律**：完整读章（序言不算读过）、缺口诚实（拿不到正文就报告）、归属三分（`[书]`/`[书→推]`/`[设计]`）、draft→simulated→field-tested 状态分级
- **三重验证**：V1 跨域（≥2处独立佐证）/ V2 预测力 / V3 独特性——防一句随口、防装饰性方法、防废话

## 使用方法

说「拷问书籍方法论」+ 你的问题。例如：

```
拷问书籍方法论。我不熟悉[领域]，现在想解决[具体问题]，希望最后得到[可检查的结果]。
```

运行产物落盘到 `qbs-runs/<run-slug>/`（问题规格书、找书决策、阅读记录、方法单元表、试跑证据）。

## 权限声明（用户须知）

| 能力类别 | 是否使用 | 说明 |
|---------|---------|------|
| 文件读写 | ✅ | 在 `qbs-runs/` 创建运行产物；在 `.trae/skills/` 创建产出子 Skill |
| 网络访问 | ✅ | 找书阶段搜索权威书单/核验目录；取文阶段下载公开托管的正文 |
| 环境变量 | ❌ | 无凭证需求 |
| subprocess | ⚠️ 可选 | 若环境有本地书库检索/OCR 工具则按需调用（均为只读查询） |
| 外部 API | ❌ | 不调用任何外部 API |

**关闭方式**：网络核验层可降级（仅用用户提供的书籍文件）；不希望写入文件可在拷问确认门前终止。
